Black Hole Observatory — methods

Three real ultramassive systems run as parallel simulations stacked in one scene, each tinted by identity: Abell 402-BCG (candidate 60±20 ×10⁹ M☉ pair — the pair that is), Holm 15A / Abell 85 (reconstructed history of the measured 2.2×10¹⁰ M☉ remnant — the pair that was), and B2 0402+379 (the confirmed 2.8×10¹⁰ M☉ pair stalled at 7.3 pc for ≳3 Gyr — the pair that is stuck).

Time stamping

Systems with a coalescence are synchronized on τ = t − t_merge: identical evolutionary phases at identical timeline positions, each lane wearing its own absolute epoch. The stalled B2 lane runs on the same absolute clock as A402 (same universe, same "today") — while the others complete the story, it stays stuck. Open its constraints and raise the loss-cone refill: it gains a coalescence and the shared τ axis rebuilds to include it.

Architecture

  • Worker-threaded physics: every lane's N-body star cluster, loss-cone classification, live 1PN+2.5PN endgame (with spin-orbit precession when spins are present), and mock photometry run in a module Web Worker (simworker.js hosting laneengine.js); star buffers travel as transferables and are ping-ponged, so the steady state allocates nothing. A synchronous fallback runs the identical engine on the main thread if workers are unavailable.
  • Rust→WASM N-body kernel: inside that worker the star-cluster KDK integrator and loss-cone classifier run as a Rust kernel compiled to WebAssembly (rust-abell85 → abell85_nbody.wasm), making 10⁵+ test particles per lane affordable — the "stars / lane" dial in the left rail goes to 131,072. Substeps are per-star adaptive: full 0.05 Myr resolution goes to stars near the holes and the cusp, while the slow outer halo takes one kick–drift–kick per frame. The kernel is a bit-exact port of the JavaScript engine (same substep rule, same float32 store/reload sequence), asserted in the test suite: identical seeds give identical clusters on either backend. The engine chip shows which backend is live; if WASM or the worker is unavailable the JS engine takes over transparently.
  • Star inspector: tap any bound star in any lane to pin a marker and trail on it and stream its live state — radius, speed, angular momentum relative to the loss-cone boundary L/L_lc = L/√(2GM_bin·a), and specific orbital energy — from the physics engine.
  • GW sonification: the dock's audio button plays the selected system's chirp, frequency-shifted by the honest factor ×3·10¹⁰ (these binaries emit at nanohertz); pitch tracks f_GW, loudness tracks log-strain.
  • ECS: an explicit entity-component-system (ecs.js) wires Timeline → Physics → Choreography → Trails → Camera → Render → HUD → Analytics → UI, one system per concern, all state inspectable.
  • Depth-separated scene: the three systems sit as distinct volumes along a shared axis — the pair that was, is, and is stuck, back to front — with the shared-τ timeline drawn as a faint physical ruler through their centers. Each lane renders into one scene with identity tinting; focus flies the camera between volumes. Floating-origin (camera-relative) uploads keep horizon zoom jitter-free. (?renderer=classic restores the original stacked composite.)
  • HDR star rendering: per-star blackbody color and luminosity drawn from a deterministic fake-IMF (cool dwarfs, a giant branch, a sparse hot tail), with special-relativistic Doppler beaming (I ∝ δ⁴) and color shift computed from each star's live velocity; bright-pass bloom and an ACES filmic tonemap.
  • Two-regime gravitational lensing: far from the holes, a thin-lens point-mass deflection with the Einstein radius computed physically from the camera distance; near the holes (when a shadow exceeds a few pixels), per-pixel null-geodesic ray tracing in the superposed Kerr-Schild metric of the two live holes, at half resolution inside screen masks that blend into the thin-lens far field where the regimes converge. The superposition η + f₁k₁k₁ + f₂k₂k₂ is an approximation, not an exact binary solution — it is exact in each hole's near zone and in the far field, and is standard practice for binary visualization. The integrator is validated against the photon capture boundary b = √27 GM/c², the Keeton–Petters deflection series, and Boyer–Lindquist capture criticals at spin (see tests/observatory-geodesic.mjs).
  • Deterministic playback: the binary's orbital phase is a pure function of the timeline epoch (validated in tests/observatory-determinism.mjs), and orbit trails draw only when playback temporally resolves the orbital period — faster playback shows the configuration without aliasing artifacts.

Open constraints, with provenance

Every dial in the left rail is labeled measured / inferred / assumed / free with its source in the tooltip — the same taxonomy as ABELL85_PAIR_RESEARCH.md. Moving a dial rebuilds that lane's full history (Chandrasekhar sink → slingshot hardening → Peters GW decay → NR-calibrated remnant), the shared τ axis, and the analytics. The physics engine and its 20-check validation contract are documented on the Abell 85 Pair lab methods panel; the full source catalog is in the repository.

Suggested experiments

  • Final-parsec stall — set Holm 15A's refill to spherical and watch its reconstruction contradict the observed single black hole.
  • Un-stick B2 0402+379 — raise its refill (triaxiality) and watch the stuck pair acquire a future coalescence on the shared axis.
  • Superkick escape — give any lane in-plane spins; the remnant leaves along its orbital angular momentum axis, out of the plane, exceeding escape velocity.
  • OJ 287-like eccentricity — e ≈ 0.65 coalesces dramatically faster (Peters 1964's (1−e²)^{7/2}).
